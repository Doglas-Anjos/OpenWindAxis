# AGENTS.md: OpenWindAxis

Read this before changing anything. OpenWindAxis is a wind resource analysis app for the browser that follows the workflows of Windographer, the desktop tool (it is not affiliated with UL Solutions). It has a Rust core compiled to WebAssembly for the browser and to a native CLI. The UI is React and TypeScript.

- **Language:** code, identifiers and doc comments are in English. The UI, `docs/` and commit messages are in Brazilian Portuguese.
- **Where the design lives:** `docs/ARQUITETURA.md` (layers, contracts, performance, tests, and §9, every decision taken). `docs/ROTEIRO.md` (the numbered steps and what is left). `docs/ESPEC-INTERFACE.md` (the original's windows, to match). `docs/PLANO.md` (the plan and principles).

## Layout

| Path | What it is |
|---|---|
| `crates/wind-core` | Pure computation: model, import, flags, rules, analyses, MCP, extrapolation. No I/O, no threads. |
| `crates/wind-api` | The wire contract. Request/response DTOs, `ErrorDto`, and the `Session` that dispatches calls. Domain types never cross it. |
| `crates/wind-wasm` | Browser binding. JSON in, JSON out; bulk series as `Float64Array`. |
| `crates/wind-cli` | The `wind` command: the same core and DTOs from a terminal. |
| `web/src` | React app. Main parts: `App.tsx` (shell, menus); `Analyses.tsx` and `windows/` (analysis windows); `dialogs/`; `workbook/` (state, the browser's IndexedDB session); `api/` (worker client and **generated** DTO types). |
| `web/public/ajuda` | The in-app help (Ajuda › Conteúdo da ajuda, F1). Generated by `docs/ajuda/capturar.mjs` and then `docs/ajuda/montar.mjs`; do not edit by hand. |
| `bench/` | Benchmarks and the end-to-end checks (`*_check.mjs`, `crosscheck.py`). |
| `samples/torre_exemplo.csv` | The sample tower the checks import. |
| `dados/` | Local measurement data. **Gitignored. Never commit it.** |
| `reference/` | Local reference material (the original's help pages). Gitignored. |

## Commands

Run them from the repository root unless noted. All are Windows/Git Bash friendly.

```sh
cargo test                           # every Rust test (core, api, cli)
cargo test -p wind-api               # also regenerates web/src/api/generated/*.ts from the DTOs
cargo build --release -p wind-cli    # target/release/wind(.exe)
cd web && npm run wasm               # core → web/src/wasm (needs the wasm32-unknown-unknown target and wasm-bindgen-cli 0.2.129)
cd web && npm run typecheck          # tsc
cd web && npx vite --port 5199 --strictPort   # dev server the browser checks expect
```

A changed DTO needs both `cargo test -p wind-api` and `npm run wasm`. Otherwise the browser rejects the new field with "unknown field".

### Checks

`node bench/check.mjs` runs all of them in order and exits with 1 when one fails; add `--ui "<chrome.exe>" http://localhost:5199/` to include the browser check (dev server running). Individually:

- **Browser UI, end to end:** `node bench/ui_check.mjs "<chrome.exe>" http://localhost:5199/ <abs path>/samples/torre_exemplo.csv <out dir>`. It drives a headless Chrome through the real menus, writes screenshots into `<out dir>` and ends with `problems: none` when it passes. Run it after any UI change.
- **Core through WASM:** `node bench/<name>_check.mjs web/src/wasm`. The names are filter, rules, edits, history, derived, confidence, methods, flag_stats and wasp_tab. These fail with a non-zero exit (assertions).
- **Recipes and CLI:** `node bench/recipe_check.mjs web/src/wasm target/release/wind samples/torre_exemplo.csv` and `node bench/cli_check.mjs web target/release/wind`.
- **Formulas:** `python -I bench/crosscheck.py samples/torre_exemplo.csv target/release/wind` checks the core against published formulas, using the standard library only.

## Using the system as a tool: the `wind` CLI

`wind` is the agent-friendly way to run analyses without a browser. Output is JSON on stdout. Failures exit with 1 (2 for usage errors) and write an `ErrorDto {"code","message"}` to stderr.

```sh
wind import samples/torre_exemplo.csv                      # dataset summary
wind analyze samples/torre_exemplo.csv histogram "column=Vel 100m Média" binWidth=1
wind analyze samples/torre_exemplo.csv shear 'columns=["Vel 100m Média","Vel 80m Média"]' sectors=1
wind export samples/torre_exemplo.csv --openwind out.csv
wind recipe <input> <analysis> --out r.json && wind replay r.json <source>   # reproducible numbers
wind run <input>... --workflow fluxo.json                  # a saved workflow on many datasets
```

`name=value` pairs fill the request DTO. Field names are the ones in `web/src/api/generated`. A missing required field comes back as `bad_request` naming it. `wind analyze --help` lists every analysis with its request and response DTO.

## Rules

1. **DTOs at every boundary.** Every wasm/CLI call takes one request DTO and returns one response DTO. The DTOs use camelCase fields, snake_case enum values, units in the names (`heightM`, `startMs`) and explicit `null`. The TS types are generated: never hand-edit `web/src/api/generated`.
2. **Names and numbers.**
   - Use descriptive names, even in short closures (`step`, `sector`, `column`, not `s`, `c`, `k`).
   - Every meaningful number is a documented `const` (limits, tolerances, table sizes, unit conversions).
   - Error texts live in the `CoreError` enum. There are no loose strings.
   - These rules apply to Rust and TypeScript alike.
3. **Documentation.**
   - `#![warn(missing_docs)]` is on. Doc comments give units, NaN behaviour, cost, errors and the reference.
   - Every decision or behaviour change gets an entry in `docs/ARQUITETURA.md`.
4. **Performance.**
   - Analysis paths read through `FilterView` and never copy columns.
   - Transcendental math goes through `libm`.
   - See ARQUITETURA §4 before touching a hot path.
5. **UI fidelity.** Match the original's layout, control order and conventions (`docs/ESPEC-INTERFACE.md`). Never copy its logo, icons, name or palette.
6. **Clean room.** Implement from public formulas, standards and the original's documented behaviour. Never copy the original's code, help text, icons or branding.
7. **Data.** Never commit `dados/` or raw measurement files; the help generator's screenshots are the only published derivative.
8. **Formatting.** Do not run prettier or reformat files you did not change. Match the surrounding code.
9. **Verification before a commit.** A change is done when all of these hold:
   - the Rust tests and `npm run typecheck` pass;
   - the relevant `bench` check passes (the UI check for anything visible);
   - ARQUITETURA has the entry.
10. **Git.**
    - Work on the current `passo-NN-*` branch. After a commit, fast-forward main: `git checkout main && git merge --ff-only <branch> && git checkout <branch>`.
    - Commit messages are in Portuguese and describe the user-visible result.

## Gotchas

- The app keeps the session in IndexedDB. Browser checks clear it at start (`Storage.clearDataForOrigin`); do the same in new ones.
- `bench/ui_check.mjs` empties its downloads folder at start, because it finds files by extension.
- In headless Chrome, a click that opens a tab needs `Runtime.evaluate` with `userGesture: true`, or the popup is blocked.
- The Vite dev server reloads open pages when files change. Do not edit sources while a browser check runs.
- ECharts is modular: register every chart and component you use (`echarts.use`).
- Flag-rule ranges are half-open, `[min, max)`.
